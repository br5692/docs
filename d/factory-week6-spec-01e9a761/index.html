5. Deliverables

D1. Salesforce (plan: operator permission set and list views 4)

  1. Permission set Portal_Operator (ours, new): read on our Account, Contact and junction fields; edit on the decision fields; the custom permissions Portal_Review_List and Portal_Deal_Decision; the Partner_Applications tab and app page; Run Flows for the two screen flows and the Apply_Registration_Decision subflow. List views carry no permission-set artifact; they stay visible to all internal users as today (W6-6). Portal_Admin_Fields keeps what it has (W5 ruling: it granted the AE permission for the demo) but no new grant lands there. Profiles untouched.
  2. List views (ours) on Partner_Influence__c: Portal_Registrations_Approved_Open (Approved, Opportunity not closed; columns Deal Name, Partner Account, Customer Account, Opportunity Stage, Estimated Value, Expected Close), Portal_Registrations_Won (Approved, Closed Won; columns add Amount and Allocation Split). Both as list cards on the app page under Portal_Review_List, after the decided card.
  3. FLS: integration set gets read on Opportunity.IsClosed, Opportunity.IsWon, Opportunity.CloseDate (Amount and Account.Commission_Rate__c are already granted; describe-proven). The Decided_* fields stay read-only for the integration user (W6-1).
  4. Autolaunched subflow Apply_Registration_Decision (ours): input registration id, decision, note; runs the conflict check, writes Registration_Status__c, Decided_By__c (running user), Decided_At__c, Decision_Note__c, one registration_decision audit row. Partner_Registration_Decision (Week 5 screen flow) calls it for the write and keeps its screens; the end-to-end suite calls it through the Flow REST API as the integration user (W6-1, option c). If the junction list-view filter on Opportunity closed state does not deploy, add an additive formula checkbox Opportunity_Closed__c on the junction (W4-12) and filter on it.

D2. Web service (plan: tiles 4; end-to-end tests 4)

  1. get_dashboard_kpis adds attributedRevenue, commission (null until the rate is set), commissionRate (null or the rate) and closeRate365 (null when undefined), computed by tool-layer/src/rules/commission.ts from one query over the caller's Approved junctions with their Opportunity fields. Allocation_Split__c and Commission_Rate__c are percent units, divide by 100. Existing four values unchanged. get_registration gains opportunity: {stage, isClosed, isWon, closeDate} (W6-2).
  2. create_deal_registration stamps Partner_Tier__c from the partner Account's Account_Tier__c when it is Tier 1, 2 or 3; blank otherwise (W6-7, OQ-3). Integration set gets read on Account.Account_Tier__c (D1.3).
  3. End-to-end contract test tool-layer/src/e2e/partner-journey.test.ts: one [TEST] partner walks apply → operator approve (quick action) → sign-in link from the log transport → contract sent and signed (quick actions) → register a deal → operator decision through the Apply_Registration_Decision subflow via the Flow REST API as the integration user (W6-1) → dashboard tiles → information reply. Every audit row asserted by action and outcome. Teardown leaves zero [TEST] rows across Account, Contact, Opportunity, Partner_Influence__c, Portal_Audit_Log__c (W4-13). Runs in the contract suite only when SF_* env is present.
  4. Health pinger for UAT: a Cloudflare Worker with a five-minute Cron Trigger (pinger/ directory, wrangler.toml, one fetch of GET /health) on the same Cloudflare account as the portal. Committed but not deployed; the planner runs the deploy before UAT and removes the trigger after (W6-4). No secret needed.
  5. Permission table unchanged. get_dashboard_kpis stays partner-only.
