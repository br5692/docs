Demo setup

Open this page on the machine you are presenting from. Drag the buttons below straight onto the bookmarks bar, then open the links further down in tabs. Nothing here needs copying or pasting.

1

Install the form fillers

Show the bookmarks bar first with Cmd+Shift+B, then drag each button onto it. Dragging installs it; clicking it here does nothing useful.

1 New company 2 Same company, new person 3 Same email again

  • 1 New company makes a brand-new company every click (a website that never repeats) with a random person. Use it for the approve case and again for the deny case. The yellow (i) domain note will show, because the email is on domestique.info and the website is not; that is the OQ-23 moment.
  • 2 Same company, new person reuses the website from the last 1 New company run with a new email and name. Approve that company first: only a People row appears, and that person is refused at sign-in until you approve them.
  • 3 Same email again reuses the last run's email and name. The page shows the usual thanks and nothing new is created (the duplicate guard).
  • All three fill every field and leave Submit to you, put the website, name and email on the clipboard, and show them in a black bar labelled with the script's number. If you are signed in to the portal, sign out first; the page will tell you.

Before you present

  1. Wake the service. It sleeps when idle and a cold start reads as a hang. Open the health check and look for ok true.
  2. Sign out of the portal, so the sign-in step starts clean.
  3. Sign out of Salesforce and back in, which clears the cached page layout.
  4. Have the inbox open in its own tab.
  5. Run the agent command from a terminal, not from inside an agent session.

The agent command

droid exec --auto high "Use the factory-portal MCP server. Call whoami, then check_partner_conflicts for domain test.com, then for domain northwind-unknown-xyz.example, then try list_applications. Report each raw result."
